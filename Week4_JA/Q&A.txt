
Q1: You're testing a legacy application that has three levels of nested iframes. 
The innermost iframe contains the elements you need to interact with, but its 
id attribute changes on every page reload (e.g., frame_4829, frame_9301, etc.). 
The outer iframe IDs are static. How would you locate and work with that dynamic 
inner iframe in Playwright? Please explain your approach and write the code to 
click a button inside that dynamic iframe.?

A: • Never rely on dynamic IDs
   • Use stable attributes + frameLocator()
   • Playwright auto-waits for frames

   Example:
   const outer = page.frameLocator('iframe[id="transaction-container"]');
   const inner = outer.frameLocator('iframe');
   await inner.getByRole('button', { name: 'Submit Transaction' }).click();

   Senior Insight: Playwright eliminates need for manual frame switching unlike
   Selenium.

Q2: In one of your test suites, you're interacting with an <iframe> (frame) that 
sometimes takes 5–10 seconds to load its content. Your test frequently fails 
because Playwright tries to interact with elements inside the frame before it's
fully loaded. How would you handle this situation in Playwright to make the test 
reliable without using arbitrary wait(5000) delays? 

A: • frameLocator() automatically waits
   • Avoid explicit waits like waitForTimeout()

   If needed:
   await expect(inner.getByRole('button')).toBeVisible();

   Approach 1: Use frameLocator() - Best Practice
   const frame = page.frameLocator('iframe[data-test="payment-frame"]');
   await frame.getByRole('button', { name: 'Pay Now' }).click();

   Approach 2: Explicit Assertion Before Action
   const button = frame.getByRole('button', { name: 'Pay Now' });
   await expect(button).toBeVisible();
   await button.click();

   Approach 3: Wait for Frame to be Attached
   await expect(page.locator('iframe[data-test="payment-frame"]')).toBeAttached();

   Note:

   What NOT to do:
   await page.waitForTimeout(5000); // Bad practice - flaky and slow

Q3:You're automating a flow where clicking a 'Print Preview' button opens a new browser 
tab. You need to verify that the new tab contains a specific text ('Invoice #1234') and 
then close that tab to return to the original tab for the next step. How would you handle 
this in Playwright? Please write the code and mention any edge cases or common pitfalls.

A: const [newPage] = await Promise.all([
     context.waitForEvent('page'),
     page.click('#open')
   ]);
   await newPage.waitForLoadState();



   Full Example:
   const [newPage] = await Promise.all([
     context.waitForEvent('page'),
     page.getByRole('button', { name: 'Print Preview' }).click()
   ]);

   await newPage.waitForLoadState();
   await expect(newPage.getByText('Invoice #1234')).toBeVisible();
   await newPage.close();
   await expect(page).toHaveTitle(/Dashboard/);

   Common pitfalls:
   • Not using Promise.all() → may miss event
   • Not waiting for page load → flaky assertions
   • Using wrong context → use context.waitForEvent('page')
   • Not closing tab → memory leaks

Q4. what is the difference between page.on and page.once?

Page.on:
--------
page.on('dialog', callback)
The callback will run every time a dialog appears, whether it’s a simple alert, confirmation, or prompt.
So if your page triggers 3 alerts one after another, the callback executes 3 times, once for each alert.

Syntax: 
-------
page.on('dialog', async dialog => {
console.log('Dialog type:', dialog.type()); // alert, confirm, or prompt
await dialog.dismiss(); // dismiss all dialogs
});


page.once:
----------

page.once('dialog', callback)
The callback will run only for the first dialog that appears, regardless of type.
After handling that first alert, it automatically stops listening.

Syntax:
-------
page.once('dialog', async dialog => {
    console.log('First dialog type:', dialog.type());
    await dialog.accept(); // only handles the first dialog
});

Q5. What is the difference between `page.frame()` and `frameLocator()`?


page.frame()
------------
Returns a Frame object, representing a specific <iframe> inside the page.

Definition:
const frame = page.frame({ name: 'iframe-name' });


Parameters:
name: Name of the iframe
url: URL of the iframe (can use regex)
Or any other frame identification

Usage: You can then call methods like fill(), click(), locator() on the frame object.

Example:

const frame = page.frame({ name: 'myFrame' });
if (frame) {
  await frame.fill('#username', 'JohnDoe');
  await frame.click('button[type="submit"]');
}

page.frameLocator()
-------------------
Returns a FrameLocator object, which allows locator-based interaction inside a frame.

Definition:
const frameLocator = page.frameLocator('#iframe-selector');

You can chain locators to interact with elements inside the iframe. Works well for nested frames.

Example:

const frameLocator = page.frameLocator('#myFrame');
await frameLocator.locator('#username').fill('JohnDoe');
await frameLocator.locator('button[type="submit"]').click();

Q6. How do you handle windows in playwright? How do you close a child window and return to the parent?

Window Handling
-------------

Window Handling is Managing/ Switching between multiple page objects (new tabs or browser windows) opened by the application within the same browser context.

Types:

Sequential Approach
-------------------
Sequential approach means handling multiple browser windows or tabs one after another in the order they open, by waiting for each new Page object and performing 
actions step-by-step.

const newPage = context.waitForEvent('page') // Pending  // Step 1 : Listener open
await page.locator(`//div[contains(text(),"MOTOROLA g35 5G")]`).click();  // Step 2 : Click action/Click Event
const childPage =   await newPage  // Step3 : Resolving the promise //The page is captured by this time// Promise is resolved ones playwright has captured the newPage
that got launched

Note: Simpler but may risk of missing the event if the page opens too quickly.
----


Concurrent Approach (Recommended)
---------------------------------

Concurrent approach in Playwright uses Promise.all() to wait for the popup and the triggering action simultaneously, ensuring reliable window handling without race 
conditions.


const [newPage] = await Promise.all([
  context.waitForEvent('page'),
  actionThatOpensNewPage()
]);

const [childPage] = await Promise.all([context.waitForEvent('page'),page.locator(`//div[text()="POCO C71 (Desert Gold, 64 GB)"]`).click()])

**Ensures you never miss the page event.

Q12. Test A runs as Admin, Test B as a standard user. Both reuse storageState to skip login. How do you ensure isolation?

Create separate browser contexts for each user state:

const adminContext = await browser.newContext({ storageState: 'adminState.json' });
const userContext = await browser.newContext({ storageState: 'userState.json' });

Avoid sharing the same storage file between parallel tests to prevent race conditions.

If parallel tests modify the same storage file at the same time, they may interfere with each other and produce unexpected results. Therefore, use separate storage 
files when the state needs to be modified.

Q: You're testing a multi-step workflow that spans three different pages (not tabs — 
actual browser windows/pages). Step 1: Login on page A. Step 2: Click a link that opens 
page B in a new window. Step 3: On page B, click a button that opens page C. Then you need 
to go back to page A to verify a toast notification appeared. How would you manage navigation 
between these three pages in Playwright? Show code for switching, verifying, and closing pages. 
Also explain how this differs from handling multiple tabs.

A: • Use browser context and keep page references

   Example:
   const pages = context.pages();
   await pages[1].bringToFront();



   Full Solution:
   // Page A - Login
   await page.goto('https://app.example.com/login');
   await page.fill('#username', 'user');
   await page.fill('#password', 'pass');
   await page.click('#login');

   // Open Page B
   const [pageB] = await Promise.all([
     context.waitForEvent('page'),
     page.getByRole('link', { name: 'Open Details' }).click()
   ]);
   await pageB.waitForLoadState();

   // Open Page C from Page B
   const [pageC] = await Promise.all([
     context.waitForEvent('page'),
     pageB.getByRole('button', { name: 'Open Report' }).click()
   ]);
   await pageC.waitForLoadState();

   // Close Page C and return to B
   await pageC.close();
   await pageB.bringToFront();

   // Close Page B and return to A
   await pageB.close();
   await page.bringToFront();

   // Verify toast on Page A
   await expect(page.locator('.toast-message')).toBeVisible();
